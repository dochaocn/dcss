# 从多源材料生成 Markdown 接口文档

## 目标

将**任意可追溯来源**中的接口定义，整理为**单一、结构稳定**的 Markdown 文件，供后续对话中向 Agent 说明「有哪些接口、如何调用、字段含义」。

## 输入来源与读取方式

| 来源 | 处理要点 |
|------|----------|
| **PDF** | 提取文字与表格；扫描版需 OCR。优先保留标题层级与表格列名。 |
| **Word（.docx）** | 按样式标题（Heading）识别章节；表格转为 Markdown 表格。 |
| **网页** | 抓取可见正文；注意折叠区块、多 Tab；记录页面标题与 URL。 |
| **表格（.xlsx/.csv 等）** | 识别表头行；多 Sheet 按「一 Sheet 一模块」或文件名映射章节。 |
| **纯文字描述** | 划分段落与列表；用户口述的「第几章」对应输出中的同级标题。 |

若环境中已启用 **pdf / docx / xlsx** 等专项技能，**优先按对应技能**读取与清洗，再进入下文「结构映射」。

## 工作流

1. **识别原文结构**  
   - 记录：文档标题、大章、小节、附录、表格、示例、错误码列表等。  
   - 若原文无明确章节，按「认证 → 公共约定 → 按资源/模块分组的接口 → 附录」推断。

2. **建立映射（不改编语义）**  
   - 原文一级标题 → 输出 `#` / `##`（保持层级对应关系，可整体降一级以避免过多 `#`）。  
   - 表格、列表、代码块：**保留为 Markdown**，不合并成长段落。  
   - 模糊或冲突处：**原样转写并加「注：原文表述为…」**，不猜测业务含义。

3. **按接口文档体裁补全（仅当原文有对应信息）**  
   - 每个接口至少对齐：名称/说明、HTTP 方法与路径、认证、请求参数、请求体、响应、错误码、示例（原文有则抄，无则留占位或省略）。  
   - 详细字段表与完整模板见 [reference.md](reference.md)。

4. **输出前自检**  
   - [ ] 章节顺序与原文逻辑一致（或已说明调整原因）。  
   - [ ] 路径、方法名、字段名、枚举值与原文一致（含大小写）。  
   - [ ] 无凭空新增的「业务规则」；推断内容已标注。  
   - [ ] 文件顶部有元信息块（见下）。

## 文件头元信息（建议）

在生成的 `.md` 最上方使用 HTML 注释或简短 frontmatter，便于 Agent 追溯：

```markdown
---
source_type: pdf | docx | web | spreadsheet | text
source_note: 文件名或 URL 摘要
generated_for: agent-api-context
---

# [服务或文档名称] 接口说明
```

若用户不需要 YAML，仅用 HTML 注释写 `来源` 与 `生成目的` 亦可。

## 与后续 Agent 的配合说明

本技能产出的 Markdown 旨在作为**单一事实来源（SSOT）**：用户在后续任务中 `@` 该文件或粘贴片段，即可让 Agent 按同一套接口定义实现调用、Mock 或测试。**因此名词与原文对齐比文风优美更重要。**
